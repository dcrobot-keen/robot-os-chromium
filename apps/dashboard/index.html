rover-01 teleop — Phase 4

Gamepad drives the rover: TeleopNode polls the Gamepad API and publishes {left, right} onto the local bus; this page's own bus subscription forwards it to createDriveDevice, which encodes a SET_VELOCITY frame and sends it through HardwareBridgeClient. The manual sliders below go through the exact same bus topic — there's no separate code path for manual vs. gamepad control. Unlike Phase 3, this tab doesn't hold its own connection: HardwareBridgeClient talks to a SharedWorker that owns the one real connection for every tab of this page. Open this page in a second tab to see it — the firmware sim's log should show only one connection opened, not two.
