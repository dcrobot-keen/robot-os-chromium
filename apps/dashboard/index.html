former-01 teleop — Phase 5

Gamepad drives the base: TeleopNode polls the Gamepad API and publishes {left, right} onto the local bus; this page's own bus subscription forwards it to createDriveDevice, which sends a Roboteq !G 1 n_!G 2 n command through the transport (see former-motor-protocol.md). Manual sliders go through the exact same bus topic — no separate code path.

Local mode connects through a SharedWorker that owns one connection for every tab of this page (Phase 4). Operator mode connects to a remote robot over a WebRTC data channel (RtcTransport) via the signaling server (Phase 5) — a host.html bridge must be running for that robot. Everything above the transport is identical in both modes; only the transport constructor changes.
